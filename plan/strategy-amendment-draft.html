The thesis this amendment encodes

In the maintainer's own words, preserved:

APM is building the best install-time package manager for AI agents. Once installation is complete, APM intentionally stops there — "your agent harness governs what runs." AgentStack should take the opposite approach. The long-term opportunity is not to build a better package manager than Microsoft. It is to become the runtime platform for AI agents: enforcing permissions and policies while agents are running; running agents inside sandboxes or lockdown environments; governing network access, secrets, and capabilities; recording and auditing everything an agent does; providing a single runtime layer that works across every AI CLI and editor.

APM manages what gets installed. AgentStack governs what is allowed to run.

Block A — the install plane, conceded

Anchor: insert into section "The shape", after the final bullet ("Everything else is quiet."), as a closing subsection of that section.

Paste payload (markdown)

### The install plane is conceded, deliberately

APM manages what gets installed. AgentStack governs what is allowed to
run. That split is a choice, not a shortfall, and this document makes it
explicit so that no queue item is ever justified by closing it.

AgentStack will not build: transitive dependency resolution (APM has a
parallel BFS graph with cycle detection and a `why` walker; ours is
`[packs]` and `[package_overrides]`, one level, and stays that way),
semver ranges against remote git tags (we pin exact refs — pinning is the
consent anchor, not a versioning convenience), `outdated` / `update` /
`prune` lifecycle tooling, or a registry race. A user who wants "install
this skill from that repo, with its dependencies, pinned, in every tool"
gets a better answer from APM today, and will keep getting one.

The complement is committed direction: APM's ecosystem — with
vercel-labs/skills and the MCP registry — is machine-readable supply for
our governed intake. It enters through the trust gate like everything
else; origin stops mattering because review does. One governed intake
path beats a competing resolver. This is the prediction that already
shipped for eve's ecosystem, extended to the install plane's winner.

Ambiguous is the one answer that costs something.

Block B — a fifth competitive tripwire: APM

Anchor: insert into section "Competitive watch" — the paragraph as a new second paragraph, after the eve paragraph and before the "2026-08 refresh" note; the tripwire as a new numbered item at the end of the tripwire list.

Paste payload — the paragraph (markdown)

APM (microsoft/apm) is the install plane's leader and, by its own
documentation, not in our plane: *"apm-policy.yml governs what gets
installed; your agent harness governs what runs. The two planes do not
overlap"*; *"APM is an install-time gate, not a runtime sandbox."* We
concede the install plane (see "The shape") and watch the stated
boundary, because stated boundaries move. Two observations date this
watch. The cadence: **~196 commits in the last 30 days, a minor release
every two weeks — v0.24.0 (2026-07-05) through v0.27.0 (2026-08-02)**.
Any tripwire on APM is re-read on that two-week clock, not once a
quarter. The precedent: **APM shipped a dashboard** — the v0.27.0 notes
carry `fix(dashboard): enforce POST body size limits` and
`fix(dashboard): harden static path traversal checks`, a served UI with a
served UI's attack surface. A project that added a graphical surface can
add a runtime one. (Both facts from `plan/apm-comparison.html`, retrieved
2026-08-04.)

Paste payload — the tripwire (markdown)

5. **APM ships a runtime enforcement plane** — anything that enforces at
   or after launch rather than at install: a sandbox, a policy check on a
   live agent, brokered network or secret access, an audit record of what
   ran. Checkable on the release notes at the cadence above.

Block C — positioning: runtime first, portability second

Anchor: insert into section "Distribution", replacing the second bullet ("The announcement leads with portability") and adding the honesty rider immediately after it.

Paste payload (markdown)

- **The announcement leads with the runtime claim** — *"One runtime layer
  that governs what your agents are allowed to run — across every CLI."* —
  with portability as the second beat: *"and your setup follows you
  everywhere."* The asymmetric first-run framing is the candidate wedge
  copy: *"you have everything in Claude Code — get it governed in Codex in
  one command."* Wedge posts may invert the emphasis locally; the launch
  itself never hitches to a competitor's name.
- **"Governs" never outruns [`ENFORCEMENT.md`](docs/ENFORCEMENT.md).**
  Host mode is cooperative; only sandbox mode is enforced. Wherever the
  copy makes the runtime claim it carries that distinction in the same
  breath — headline, README, first-run, demo. This is "Claims match
  enforcement" applied to our own marketing: an advisory check is not
  confinement, recording is not prevention, and an allowed destination can
  still exfiltrate. A positioning flip that loses this line is not
  adopted.

Block D — the buyer stays; the future buyer gets a name

Anchor: the paragraph into section "Distribution", after the "Beachhead pair" bullet; the trigger as a new numbered item in "The plan" → "Revisit triggers".

Paste payload — the paragraph (markdown)

The beachhead does not move. The audience is still the developer
personally running two or more coding CLIs, and first-run material still
demonstrates Claude Code + Codex flawlessly. The runtime thesis has a
further consequence — central policy, fleet audit, and compliance are
what a team asks a runtime layer for — and naming it is not starting it.
**The team and enterprise buyer is not a current lane.** "No enterprise
administration suite" stays in the non-goals until the trigger below
fires.

Paste payload — the revisit trigger (markdown)

4. **The team buyer asks** — fires when the activation study has run and
   a retention signal exists, **and** a team asks for central policy or
   fleet audit. Both halves are required: an ask without evidence of
   individual retention is a distraction, and evidence without an ask is
   a guess. Reopens this document to decide whether the enterprise
   non-goal holds.

Block E — one consequence for the queue

Anchor: none in STRATEGY.md — this is TODO.md territory, recorded here so the adoption is coherent. The maintainer should mirror it in TODO.md. If he wants it visible in the strategy, the natural home is one sentence in "The plan", under the queue list.

Paste payload (markdown)

The runtime thesis makes `run` and `workflow` load-bearing: they are the
two entry points of the runtime plane, and they are the least verified
surfaces we have (plan item P8). Verification of both rises in priority
and lands before the bar is judged. A thesis that the runtime layer is
the product cannot rest on the two verbs nobody has proven.

What this amendment does not change

  • The shape — the committed set is unchanged; conceding the install plane removes nothing from it and adds nothing to it.
  • What never changes — every invariant holds verbatim; Block C tightens "Claims match enforcement" rather than touching it.
  • The bar — still the maintainer's own satisfaction, still first, still before any other person sees the product.
  • The non-goals — all of them stand, including "no enterprise administration suite"; Block D names a future buyer and starts nothing.
  • The standing constraints — the CLI remains the primary surface and the sole authority, and the embedded dashboard stays removed. APM shipping a dashboard is a divergence to record, never a gap to close.
