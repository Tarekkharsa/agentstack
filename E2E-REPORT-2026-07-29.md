# AgentStack + T3 Code end-to-end validation

Date: 2026-07-29
AgentStack: `4141f60`, release binary `agentstack 0.17.0 (sandbox: no)`
T3 Code: `5745a905a`

## Verdict

The AgentStack CLI is healthy across its normal, feature-gated, documentation,
example, security, and real-adapter test paths. The current T3 Code integration
is broadly functional: a real browser completed setup, drift repair, guard
installation, trust review, toolset creation/editing/renaming/deletion,
temporary activation and restore, activity/protection inspection, and undo
against the real v0.17 binary.

It is not accurate to say that CLI/UI parity is complete. Two UI defects and
two missing UI projections remain:

1. An uninitialized project is labelled **Ready** in the panel header while the
   body and CLI correctly report `needs_setup`.
2. A refused profile-edit preview loses the CLI error. For example, deleting
   the only toolset is correctly refused by the CLI because it would widen
   access, but T3 displays the unrelated “preview has no digest; update
   agentstack” message.
3. The CLI's `doctor-probe-v1` live server startup check has no T3 contract
   field, action, or result UI.
4. The CLI's `workflow-serial-roles-v1` scheduling warning is dropped by T3's
   workflow decoder, so the monitor cannot explain that some roles serialize
   despite a higher concurrency limit.

There are also documentation gaps: the integration capability table is behind
the shipped contract list, T3 has no AgentStack integration documentation, and
the workflow guide's “passed its independent security review” wording conflicts
with the retained promotion-blocking review findings.

## Findings and gaps

### F1 — Setup state is mislabelled Ready

Severity: medium

Reproduction:

1. Open a Git project with no AgentStack manifest.
2. Open the AgentStack panel.
3. The header says **Ready**, while the body says the project is not set up.
4. `agentstack doctor --json` reports `"state": "needs_setup"`.

Cause: the header derives only from `concern`; setup is handled in a separate
body branch and is not a concern. The header expression is
`concern ? "Needs you" : "Ready"` in T3
`apps/web/src/components/agentstack/AgentstackControl.tsx`.

Recommended fix: derive one top-level posture from `setupState`, reachability,
compatibility, doctor state, concern, and active run, then use it for both the
trigger dot and header label. Add a regression test asserting that
`needs_setup` never renders Ready.

### F2 — Failed edit previews discard the real CLI refusal

Severity: medium

The CLI correctly reports:

> won't delete 'spare' — it is the only toolset here, and with none declared
> every server in the manifest becomes reachable...

T3 instead reports:

> This agentstack CLI's preview has no digest... Update agentstack...

The server parses only successful JSON from stdout and returns `preview: null`;
the UI maps every null preview to the old-CLI/no-digest explanation. Exit code
and stderr are not preserved in `profileEditPreview`.

Recommended fix: return a discriminated preview result containing
`preview | refusal | incompatible | unavailable`. Preserve a bounded,
sanitized CLI refusal message. Reserve “no digest/update” for a successfully
decoded legacy preview that genuinely lacks the consent digest.

### F3 — `doctor-probe-v1` is CLI-only

Severity: product gap

The CLI advertises `doctor-probe-v1` and `doctor --probe --json` returns
structured `ran`, `skipped_reason`, and per-server results. The live test
correctly returned `ran: false, skipped_reason: "drifted"` after the UI edits
invalidated trust.

T3's `AgentstackDoctorReport` schema has no `probe` field and the panel has no
“test server startup” action or result view. This is a meaningful difference:
normal doctor checks configuration; probe actually starts, handshakes with, and
reaps stdio servers.

Recommended fix: add a separately authorized read/action path gated strictly on
`doctor-probe-v1`, show the side-effect warning, and render structured results.

### F4 — `workflow-serial-roles-v1` is dropped

Severity: product gap

AgentStack workflow rows carry `serial_roles`, naming harnesses that cannot take
per-child MCP config and therefore run one at a time. T3's
`AgentstackWorkflowSummary` schema includes `roles` and limits but not
`serial_roles`, and it has no feature gate/display for
`workflow-serial-roles-v1`.

Recommended fix: decode the optional field only when that contract is
advertised and show an explicit scheduling warning in workflow list/monitor
views.

### F5 — Contract and product documentation is behind the implementation

Severity: documentation

- `docs/integrations.md` says the table covers every panel contract, but omits
  batch membership editing, rename, delete, serial-role observation, doctor
  probe, and JSON reads.
- The design contract example also omits the newer profile/library/probe
  contracts.
- T3 Code has no AgentStack integration guide in its README/docs.
- `docs/workflows.md` says the interpreter passed independent security review;
  the dated review and current TODO retain promotion-blocking watchdog,
  interpreter-memory, re-entrancy, instruction-budget, determinism, and
  crate-boundary findings. “Reviewed and acceptable while experimental” would
  match the evidence better than “passed.”
- The control-plane design still lists profile authoring as deferred, although
  create, membership editing, rename and delete now ship in the panel.

Recommended fix: generate the contract table/example from the CLI feature
constant, add a T3 user/developer integration page, and reconcile experimental
workflow wording with the current promotion checklist.

### Intentional CLI/UI differences

These are not regressions unless full terminal equivalence is the product goal:

- T3 does not expose registry search/add, arbitrary server/skill authoring,
  instructions, generic policy editing, secret-value entry, export/import,
  sign/verify, sandbox/lockdown execution, workflow authoring/run/resume, or
  generic `run`/`kill`.
- The panel is a reviewed setup/status/toolset/observation surface; the CLI
  remains the complete interface.
- The AgentStack control exists in T3 web/desktop's shared web UI. No equivalent
  AgentStack feature exists in `apps/mobile`.
- Structured denial JSON is still a design item; T3 currently derives denial
  cards from the stable guard reason string.

## What was not proven locally

- Docker was not running, so a real `--sandbox`/`--lockdown` container launch
  could not be executed. Both feature-gated code paths compiled and linted, and
  their Rust tests passed.
- Only the installed Claude and Codex CLIs received live conformance probes.
  Golden render tests cover all adapters, but the nightly adapter matrix is
  still the right place for real-version drift detection.
- Not-installed, incompatible-schema, legacy-feature, malformed-JSON, library
  removal, workflow run monitoring, and concurrent refresh races were covered
  by focused automated tests rather than separate live-browser fixtures.
- T3 mobile has no AgentStack surface to exercise.

## Recommended E2E automation

1. **Add a cross-repository real-binary job.** Build AgentStack release once,
   inject it through `T3CODE_AGENTSTACK_BIN`, and run T3's bridge plus browser
   suite against the artifact.
2. **Create an isolated browser fixture.** Give every test fresh `HOME`,
   `AGENTSTACK_HOME`, T3 state, Git project, Claude JSON and Codex TOML. Cover
   `needs_setup → setup → drift → apply → guard → toolset → trust → session →
   restore → undo`.
3. **Generate contract parity tests.** Read AgentStack's `FEATURES`, require T3
   to classify each as supported, intentionally CLI-only, or unsupported with
   an owner. For supported contracts, assert schema fields and UI gates.
4. **Preserve CLI failures structurally.** Add a bridge E2E test for deleting
   the last toolset and assert that the exact refusal category reaches the UI.
5. **Test a version matrix.** Run current T3 against current and previous
   AgentStack releases, and current AgentStack against the previous T3 contract
   fixtures. Assert absent contracts fail closed with accurate guidance.
6. **Keep Docker enforcement separate.** Use a Linux CI job with Docker for
   real sandbox/lockdown launch, egress denial, cleanup, timeout and orphan
   checks.
7. **Add visual/a11y assertions.** Capture the AgentStack panel/dialog at the
   supported desktop widths, run axe/keyboard checks, and explicitly mark
   mobile unsupported until a mobile surface is planned.
8. **Generate docs from contracts.** Fail CI when the integrations table and
   example feature envelope differ from `ui_contract::FEATURES`.

The highest-value first automation is the isolated browser fixture plus the
cross-repository contract classifier. Together they would have caught both
observed UI defects and both silent capability omissions.
