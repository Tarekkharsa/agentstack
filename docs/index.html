One agent setup. Every coding CLI.

AgentStack collects the MCP servers, skills and instructions you already use into one .agentstack/ directory in your project, then renders them back as native configuration for every supported CLI. Named toolsets switch by project or task, and every change stays understandable and recoverable.

quick start

Five minutes to first value

Three commands, then plain files you can open, read and commit.

Prefer guided? Take the tutorial →
bash
$curl -fsSL https://raw.githubusercontent.com/Tarekkharsa/agentstack/main/install.sh | sh
$agentstack init# guided wizard: your CLI configs → one manifest
$agentstack status# is it ready — and the one thing that fixes it
your-project/
your-project/ ├── .agentstack/ │ ├── agentstack.toml # everything your tools may run: servers, skills, instructions │ └── .env # token values lifted out of your configs (only when init found any) └── .gitignore # one managed line, so that .env is never committed
  • Guided wizard: your CLI configs → one manifest.
  • Status says whether it is ready — and the one thing that fixes it.
  • What it leaves behind is plain files you can open, read and commit.

agentstack yes, undo, up, share, and receive are v0.18.0 and later; the install line above serves the current stable release. agentstack --version says which you have.

.agentstack/agentstack.toml records your whole setup — the manifest. Every CLI-specific file AgentStack writes is rendered from it, and can be regenerated or taken back off at any time. Mostly the system writes it for you — and when you write a skill of your own you don't open it at all: drop the folder under .agentstack/skills/, run agentstack yes, review once, and it is live in every CLI. It holds ${GITHUB_TOKEN}-style placeholders, never the token values.

That is the run replayed at the top of this page. Reproduce it fenced with examples/first-value-demo/run-demo.sh — it asserts every step, so the recording stays accurate.

the everyday loop · one deliberate yes

What using it feels like

Four moments, captured from v0.18.0-rc.2 exactly as it prints them — a capture, not a mockup. Everything is automated except the one thing that never is: your yes.

$ agentstack yes → 1 dropped file ready to go live in this project: + skill summarize (./skills/summarize) your own work — untracked in git ✓ pinned 1 skill This will write: Claude Code → 1 skill to symlink into .claude/skills Codex CLI → 1 skill to symlink into .agents/skills …

Write a skill: drop the folder, say yes. No manifest edit — it is pinned, recorded, and live in every CLI. The one-step review is only for work that is provably yours; anything that arrived with a clone gets the full staged review. Add a skill →

$ agentstack undo recent changes (newest first) 1 just now init 1 file · Claude Code, Codex CLI, Gemini CLI, … pick a point: agentstack undo --to <n> --write

Take it back, from a timeline. Every write is recorded before it lands; pick a point and revert to it. The revert is recorded too — going one step too far is recoverable. Undo anything →

blocked: web-search tried to reach api.evil.example — not in this project's allowed hosts ([policy.egress]) nothing was sent · add the host to [policy.egress] if you meant to allow it

The seatbelt speaks plainly. A denial says what was stopped, why, that nothing happened, and the one safe next step — backed by a recorded event, on the paths where enforcement really runs.

$ agentstack share backend # signed as part of sharing — signing is not a flag $ agentstack receive team.astack # staged inert and carded first; a recognized publisher # makes the card shorter — never optional

Sharing is signing; receiving is reviewing. A bundle carries the manifest, lock, and pinned content. Nothing a teammate receives activates without their own yes. Share a setup →
