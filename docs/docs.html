One setup.
Every agent.

Keep reusable capabilities in your own Git library. Let each project select a small toolset. AgentStack pins it, reviews it, and serves it to every supported CLI without copying MCP and skill files everywhere.

$agentstack statusready: reviewed, locked, and available to every connected CLI
The whole model
01Your central library

A normal Git repo with skills, MCP servers, and instructions for all projects and machines.

02Each project

A readable manifest selects names. Its lock freezes the exact resolved content.

03Each agent

The trusted default opens automatically. Skills and MCP tools load only when needed.

Most-used commands

CommandWhy you run it
agentstack statusSee whether this project is ready and get one next action.
agentstack lib sourcesSee all central-library sources, their order, and collisions.
agentstack lockPreview the exact library content a project would accept.
agentstack trust .Human review after the manifest or lock changes.
agentstack upPreview syncing the library and reconciling this machine.
agentstack doctorRun the deep check only when status points to a problem.
agentstack undoReview and reverse AgentStack-managed writes.

Common questions

What does the lock mean?

It pins the exact library bytes and prevents silent project updates.

How does the agent see skills?

Names and descriptions first; one full body only when the task matches.

Can I use several libraries?

Yes. They form one ordered view, and collisions are explicit.

CLI and model instructions?

Use reusable variants with deterministic, most-specific selection.

Is it for you?

Useful when your setup starts multiplying.

Use AgentStack for several CLIs, projects, machines, or teammates—especially when you want reusable private capabilities and reviewed updates. For one CLI with one permanent config and nothing to share, native configuration may be enough.
